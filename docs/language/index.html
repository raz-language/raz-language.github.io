Language guide

The core semantic model behind Raz 1.0: types, ownership, abstractions, control flow and explicit low-level boundaries.

LANGUAGE MODEL

Native software with a visible cost model.

Raz is statically typed and designed around deterministic resource management. Ordinary code uses ownership, moves and borrowing rather than a mandatory tracing collector; deliberate low-level work is isolated behind explicit native and unsafe boundaries.

Stable 1.x contract

Raz 1.0 is documented as stable. The language specification is the normative contract and the conformance suite is its executable counterpart.

TYPES

Systems-level data without giving up structure.

The stable model includes structs, payload enums, tuples, arrays, slices, references, raw pointers and function pointers, along with scalar numeric, logic, character and string types.

OWNERSHIP

Deterministic lifetime, compiler-checked.

Moves, borrows, non-lexical loan analysis, lifetime-aware slices and deterministic drop establish ownership at compile time. The goal is to keep resource lifetime understandable from source without imposing a tracing ownership runtime.

ABSTRACTION

Generics and traits without hiding the backend.

Raz provides generics, traits, associated items, const generics, closures and iterators. Generic code monomorphizes, while dynamic dispatch occurs only where requested by the program.

CONTROL FLOW

Pattern matching, structured errors and deterministic cleanup.

Payload enums and match support structured data flow. The language also includes structured error handling, defer, compile-time facilities and deterministic destruction.

LOW-LEVEL BOUNDARY

Unsafe operations are deliberate boundaries.

Raw pointers, explicit extern integration and unsafe operations keep systems work possible without making every caller participate in the same level of risk.
