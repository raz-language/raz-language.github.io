Compiler guide

How Raz lowers one verified language into native code, WebAssembly and RXE bytecode.

COMPILER PIPELINE

Semantics first. Backends second.

Raz parses and analyzes source once, lowers it into typed HIR, then into backend-neutral verified MIR. Diagnostics, language tooling and code generation share that semantic foundation.

Raz source→Typed HIR→Verified MIR→Backends

FORGE

The bundled default native backend.

Forge is integrated in-process for ordinary native compilation on supported x86-64 hosts and is also maintained as a standalone repository/tool suite. Experimental AArch64 object paths are present while ordinary AArch64 builds continue to prefer LLVM until qualification reaches parity.

Forge repository ↗

LLVM

A production native option from the same MIR.

The Raz-written LLVM path emits textual LLVM IR and can delegate final native object/executable generation to an installed Clang/LLVM toolchain.

PORTABLE TARGETS

WebAssembly and RXE.

WebAssembly emits portable .wasm under a documented ABI. RXE provides a specified portable bytecode format for runtime-oriented execution.

Portable targetsRXE format ↗

LINKING

ObLink owns the native linker path.

ObLink is a separate repository in the Raz workspace and provides the native linking component used by the toolchain.

ObLink repository ↗

SELF HOSTING

The production compiler is written in Raz.

The bootstrap flow constructs the production compiler and verifies compiler reproducibility before producing the toolchain. Native C/C++ code remains at permanent host/runtime/backend boundaries rather than acting as a second evolving frontend.
